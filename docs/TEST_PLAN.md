# 测试计划

> 本文档定义片场租赁计时管理系统的测试策略、测试用例和验收标准。
>
> **测试目标**：验证 MVP 核心业务闭环的完整性和正确性

---

## 1. 测试目标

验证核心业务闭环：

```
注册 → 充值 → 入场 → 计时 → 离场 → 预账单
    → 管理员确认 → 扣款 → 放行
```

以及以下关键功能的正确性：

- 状态机流转（订单状态、审核状态）
- 计费规则（场地按时间、设备按次）
- 权限控制（会员、管理员）
- 操作日志（完整可追溯）

---

## 2. 测试范围

### 2.1 覆盖范围

| 模块 | 测试内容 |
|------|----------|
| **M2 认证与会员** | 登录、注册、充值、余额管理、退出 |
| **M3 会话与计时** | SKU选择、入场、计时、离场、预账单 |
| **M4 管理员端** | 登录、审核（部分人离场/账单/补差价）、放行、CRUD |
| **M5 日志与审计** | 操作日志记录、状态流转日志 |

### 2.2 不覆盖范围

| 类别 | 原因 |
|------|------|
| UI 像素级测试 | 非核心验收标准 |
| 动画效果 | 视觉层面，不影响功能 |
| 真实微信授权 | 演示系统使用假授权 |
| 真实支付接口 | 演示系统使用模拟充值 |
| 压测 | MVP 阶段不涉及 |
| 渗透测试 | 安全基线已由框架保障 |

---

## 3. 测试策略

### 3.1 测试金字塔

```
        /\
       /E2E\      ← 关键业务流程端到端
      /------
     /集成测试\    ← 模块间交互
    /----------
   /单元测试\     ← 状态机、计费逻辑
  /------------\
```

| 层级 | 占比 | 工具 |
|------|------|------|
| 单元测试 | 60% | Vitest |
| 集成测试 | 30% | Vitest + Supertest |
| E2E | 10% | Playwright |

### 3.2 测试优先级

| 优先级 | 定义 | 示例 |
|--------|------|------|
| P0 | 核心闭环，一票否决 | 入场→离场→扣款→放行 |
| P1 | 单模块核心功能 | 计费计算、状态机流转 |
| P2 | 边界条件 | 余额为0时入场、并发入场 |
| P3 | 异常处理 | 网络超时、数据校验 |

## 7. 验收标准

### 7.1 核心闭环验收

| 步骤 | 验收条件 |
|------|----------|
| 注册 | 新用户可注册并自动登录 |
| 充值 | 充值后余额正确增加 |
| 入场 | 订单创建，状态 entering，计时开始 |
| 离场 | 申请成功，状态 pending_exit |
| 审核 | 管理员可查看并审核 |
| 扣款 | 余额正确扣除 |
| 放行 | 订单状态 completed |

### 7.2 状态机验收

| 状态 | 可转换状态 |
|------|-----------|
| entering | → partial_exit_pending, → pending_exit |
| partial_exit_pending | → entering |
| pending_exit | → topup_pending, → reviewing |
| topup_pending | → reviewing |
| reviewing | → completed |
| completed | - (终态) |

### 7.3 计费验收

| 场景 | 预期费用 |
|------|---------|
| 场地A 2.5小时 | ¥50 × 2.5 = ¥125 |
| 场地A 3小时 + 设备B 2次 | ¥50 × 3 + ¥20 × 2 = ¥190 |
| 基础费用 ¥100 + 额外¥50 | ¥150 |

### 10.4 测试用例版本管理

- **测试用例编号规则**: `[模块]-[序号]-[版本]`
  - 例如: `T2-1-v1` 表示 M2 模块第 1 个测试用例第 1 版本
- **版本更新条件**:
  - 功能需求变更导致测试逻辑变化
  - 发现测试用例错误或遗漏
  - 边界条件补充
- **更新记录**: 在测试文件注释中记录变更历史

### 10.5 常见问题处理

| 问题 | 处理方式 |
|------|----------|
| 测试失败 | 分析失败原因，修复代码或更新测试用例 |
| 需求变更 | 评估影响范围，更新相关测试用例 |
| 新增功能 | 补充测试用例，优先覆盖 P0/P1 |
| 测试数据依赖 | 使用 Mock 数据，确保测试独立性 |
| 异步测试 | 使用 async/await 或 Vitest 的 await for |

### 10.6 测试数据管理

- **种子数据**: `prisma/seed.ts` 初始化基础测试数据
- **测试夹具**: 每个测试文件使用 `beforeEach` 重置状态
- **Mock 策略**: 
  - 外部依赖（API、数据库）使用 Mock
  - 内部业务逻辑使用真实实现
