# MVP 需求边界文档

## 项目名称

片场租赁计时管理系统

---

## 一、核心业务流程（完整复述）

```
入场 → 选场地设备 → 计时使用 → 离场申请 → 余额判断 →
管理员审核(核验+调价) → 扣款 → 开门放行
```

---

## 二、角色定义

| 角色 | 描述 | 操作权限 |
|------|------|----------|
| 会员用户 | 剧组负责人（制片/外联/场务） | 扫码入场、选择场地设备、申请离场、补差价、申请部分人离场 |
| 管理员 | 片场现场人员 | 审核账单、核验资产、调整金额、确认扣款、放行、审核部分人离场 |

---

## 三、功能列表（MVP范围）

### 3.1 会员管理

- [x] 假授权登录：前端弹窗，用户点击"同意"后 localStorage 存储假用户信息
- [x] 会员充值：模拟充值，不调用真实支付接口，仅增加虚拟余额
- [x] 会员余额查询
- [x] 必须充值后才能入场（硬性约束）

### 3.2 场地与设备管理

- [x] 场地列表（不同场地不同价格）
- [x] 设备列表（可选租赁设备及价格）
- [x] 入场时选择本次使用的场地和设备
- [x] 价格配置（按小时/按次）

### 3.3 入场

- [x] 扫码识别会员身份（模拟）
- [x] 未注册引导注册+充值
- [x] 选择场地和设备
- [x] 记录入场时间
- [x] 模拟开门放行
- [x] **不可中途换负责人**
- [x] **部分人离场**：程序内操作，输入离场人数+备注 → 产生日志 → 通知管理员 → 管理员手动放行

### 3.4 离场

- [x] 负责人扫码申请离场
- [x] 系统计算费用（基于时长+场地+设备）
- [x] 余额充足 → 推送账单给管理员
- [x] 余额不足 → 提示补差价，用户充值后推送账单
- [x] 补差价需管理员审核通过后才生效

### 3.5 管理员审核

- [x] 收到账单通知
- [x] 查看使用详情（入场时间、场地、设备、时长）
- [x] 资产核验（人工检查）
- [x] **可添加额外费用**（损坏赔偿、清洁费等）
- [x] 确认扣款
- [x] 模拟开门放行

### 3.6 操作日志

- [x] 扫码开始（入场记录）
- [x] 人员进出（剧组人员进出场记录）
- [x] 部分人离场申请（人数+备注）
- [x] 管理员审核部分人离场
- [x] 申请离场
- [x] 补差价申请
- [x] 管理员审核（含调整金额记录）
- [x] 已扣款（金额、时间、操作人）
- [x] 已放行
- [x] 管理员可查看日志列表
- [x] 管理员收到关键事件通知

## 四、Scope Out（明确不做）

| 功能 | 原因 |
|------|------|
| 微信授权注册/登录 | MVP使用假授权弹窗 |
| 真实支付接口 | MVP仅模拟充值 |
| 多门店支持 | MVP单门店 |
| 对公转账/月结 | 仅支持会员余额支付 |
| 人员数量精确记录与计费 | 剧组多人进出仅作日志，不影响计费 |
| 设备损坏自动识别 | 人工核验 |
| 实时费用推送（使用中） | 仅离场时计算 |
| 发票管理 | 后续迭代 |
| 数据导出/报表 | 后续迭代 |

## 六、非功能性需求

| 项目 | 要求 |
|------|------|
| 部署方式 | 本地部署（Docker） |
| 数据存储 | PostgreSQL |
| 通知方式 | MVP：系统内消息 + 模拟通知 |

---

## 七、关键约束

1. **入场前提**：会员余额 > 0
2. **离场前提**：管理员确认扣款成功
3. **负责人约束**：一次入场不可更换负责人
4. **计费依据**：入场时间 + 场地 + 设备 + 管理员调整
5. **部分人离场**：需管理员手动操作放行

## 八、数据模型（草稿）

### 会员（Member）
- id, name, phone, balance, created_at

### 场地（Venue）
- id, name, price_per_hour, description

### 设备（Equipment）
- id, name, price_per_use, description

### 订单（Order）
- id, member_id, venue_id, entry_time, exit_time, status, total_amount, final_amount

### 订单设备（OrderEquipment）
- id, order_id, equipment_id, quantity

### 操作日志（OperationLog）
- id, order_id, action, operator_type, operator_id, details, created_at
