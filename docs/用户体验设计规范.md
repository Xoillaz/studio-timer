# 用户体验设计规范

> 本文档定义片场租赁计时管理系统的用户体验设计原则

---

## 一、信息 & 交互形态

### 1.1 场景决定形态

| 终端 | 形态 | 说明 |
|------|------|------|
| 用户端 | 移动端 H5 | 手机扫码进入，竖屏优先 |
| 管理员端 | 响应式 | 手机/电脑自适应 |

### 1.2 核心交互

- 扫码
- 看时间
- 看金额
- 确认

### 1.3 形态原则

| 原则 | 说明 |
|------|------|
| 一屏一个主任务 | 每个页面只完成一个核心动作 |
| 关键数字大而醒目 | 时间、金额、余额使用大字号突出显示 |
| 状态用颜色 + 文字双重表达 | 不能只靠颜色区分状态，必须有文字说明 |
| 危险操作二次确认 | 扣款、放行等操作需要用户二次确认 |

## 二、H5 原生规范

### 2.1 必须使用的 Web 标准

```html
<!-- 移动端视口 -->
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">

<!-- 语义化标签 -->
<header> <main> <nav> <button> <form> <section>

<!-- CSS 变量做主题 (tokens.css) -->
:root {
  /* 颜色 */
  --color-primary: #1677ff;
  --color-success: #52c41a;
  --color-warning: #faad14;
  --color-danger: #ff4d4f;
  --color-text: #1f1f1f;
  --color-text-secondary: #8c8c8c;
  --color-bg: #f5f5f5;
  --color-card: #ffffff;

  /* 间距 */
  --space-xs: 4px;
  --space-sm: 8px;
  --space-md: 16px;
  --space-lg: 24px;
  --space-xl: 32px;

  /* 字号 */
  --font-sm: 12px;
  --font-md: 14px;
  --font-lg: 16px;
  --font-xl: 20px;
  --font-xxl: 28px;

  /* 圆角 */
  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 12px;

  /* 阴影 */
  --shadow-card: 0 2px 8px rgba(0,0,0,0.06);
}

<!-- localStorage 存 token -->
localStorage.setItem('token', token);
localStorage.getItem('token');

<!-- History API 做页面栈 -->
history.pushState({}, '', '/new-page');
window.onpopstate = () => { /* 处理返回 */ };
```

### 2.2 移动端适配

| 规范 | 实现方式 |
|------|----------|
| 尺寸单位 | `rem` + `vw` 混合，或 `px` + `clamp()` |
| 触摸目标 | 最小 44×44px |
| 底部安全区 | 使用 `env(safe-area-inset-bottom)` 避开 iPhone 刘海 |
| 数字键盘 | 输入框使用 `type="number"` |
| 防止缩放 | `touch-action: manipulation` |

```css
/* 底部固定操作栏示例 */
.fixed-bottom {
    padding-bottom: calc(20px + env(safe-area-inset-bottom));
}

/* 数字字体 */
.monospace {
    font-variant-numeric: tabular-nums;
}
```

### 2.3 不要做的

| 不要做 | 说明 |
|--------|------|
| 复杂 UI 框架 | 不使用不熟悉的重量级框架 |
| PC 端复杂后台 | 管理员端手机也能操作 |
| 追求原生 App 体验 | H5 就是 H5，保持轻量 |

## 三、信息组织合理性

### 3.1 用户端信息优先级

| 优先级 | 问题 | 说明 |
|--------|------|------|
| 1 | 我现在是什么状态？ | 未入场 / 使用中 / 待确认 / 已完成 |
| 2 | 已经用了多久？预计多少钱？ | 计时器和预估费用 |
| 3 | 我的余额够不够？ | 余额状态提示 |
| 4 | 下一步该做什么？ | 明确的行动按钮 |

### 3.2 管理员端信息优先级

| 优先级 | 内容 | 说明 |
|--------|------|------|
| 1 | 有几单待确认？ | 待审核数量徽章 |
| 2 | 每单是谁、用了多久、预账单多少？ | 订单概要 |
| 3 | 资产清点结果？ | 备注信息展示 |
| 4 | 调价入口？ | 额外费用输入框 |
| 5 | 确认扣款 / 放行按钮？ | 操作按钮 |

### 3.3 设计原则

| 原则 | 说明 |
|------|------|
| 状态机状态映射 UI | 订单状态直接对应页面展示 |
| 一页一问题 | 每个页面只回答一个核心问题 |
| 等宽数字字体 | 金额、时间使用 `font-variant-numeric: tabular-nums` |

```css
/* 等宽数字 */
.amount, .time {
    font-variant-numeric: tabular-nums;
    font-family: 'SF Mono', 'Roboto Mono', monospace;
}
```

## 四、交互一致性

### 4.1 按钮样式

| 类型 | 用途 | 样式 |
|------|------|------|
| 主按钮 | 关键操作（入场、确认扣款） | 填充色.primary，文字白色 |
| 次按钮 | 次要操作（取消、返回） | 边框.primary，文字.primary |
| 危险按钮 | 危险操作（放行、删除） | 填充色.danger，文字白色 |

```css
.btn-primary {
    background: var(--color-primary);
    color: white;
    border-radius: 8px;
    padding: 12px 24px;
    min-height: 44px;
}

.btn-secondary {
    background: transparent;
    color: var(--color-primary);
    border: 1px solid var(--color-primary);
}

.btn-danger {
    background: var(--color-danger);
    color: white;
}
```

### 4.2 反馈状态

| 状态 | 场景 | 实现方式 |
|------|------|----------|
| 加载中 | 请求处理中 | 按钮禁用 + 加载图标 + "处理中..." |
| 成功 | 操作完成 | 绿色提示 + "操作成功" |
| 失败 | 操作失败 | 红色提示 + 错误原因 + 解决办法 |
| 空状态 | 无数据 | 插图 + 提示文案 |

### 4.3 文案统一

| 统一用词 | 说明 |
|----------|------|
| 入场 | 不要用"进场" |
| 离场 | 不要用"出场" |
| 确认扣款 | 不要用"结算" |
| 放行 | 不要用"开门" |

### 4.4 格式统一

| 格式 | 标准 | 示例 |
|------|------|------|
| 时间格式 | `YYYY-MM-DD HH:mm` | 2026-01-14 14:30 |
| 金额格式 | `¥0.00` | ¥100.00 |
| 错误提示 | "发生了什么 + 怎么办" | "网络错误，请检查网络后重试" |

## 五、页面状态示例

### 5.1 用户端状态映射

| 订单状态 | 页面标题 | 主按钮 | 色调 |
|----------|----------|--------|------|
| `pending_entry` | 选择场地 | 确认入场 | primary |
| `entering` | 使用中 | 申请离场 | success |
| `partial_exit_pending` | 部分人离场待审核 | 无 | warning |
| `pending_exit` | 申请已提交 | 无 | warning |
| `topup_pending` | 补差价待审核 | 无 | warning |
| `reviewing` | 审核中 | 无 | warning |
| `rejected` | 申请被拒 | 重新申请 | danger |
| `completed` | 已完成 | 完成 | success |

### 5.2 管理员端状态映射

| 待审核类型 | 徽章 | 入口 | 操作 |
|------------|------|------|------|
| 部分人离场 | 红色数字 | 审核列表 | 同意/拒绝 |
| 账单审核 | 红色数字 | 审核列表 | 确认扣款/拒单 |
| 补差价 | 红色数字 | 审核列表 | 同意/拒绝 |

## 七、错误处理规范

### 7.1 错误提示模板

```
{发生了什么}，{怎么办}
```

| 错误场景 | 提示文案 |
|----------|----------|
| 网络错误 | "网络连接失败，请检查网络后重试" |
| 参数错误 | "信息填写有误，请检查后重新提交，API错误码为￥{错误码}" |
| 余额不足 | "余额不足，需要充值 ¥{差额} 才能继续" |
| 订单状态错误 | "当前状态无法执行此操作，请刷新页面重试" |
| 权限不足 | "您没有权限执行此操作" |

### 7.2 表单验证

| 字段 | 规则 | 错误提示 |
|------|------|----------|
| 姓名 | 必填，2-20字符 | "请输入姓名（2-20个字符）" |
| 手机号 | 必填，11位数字 | "请输入正确的手机号" |
| 充值金额 | 必填，大于0 | "请输入正确的充值金额" |
| 离场人数 | 必填，大于0 | "请输入离场人数" |
